보안은 기능 하나를 켜고 끄는 일이 아니라, 저장·기억·공유·연결·인증이 어디까지 이어지는지 관리하는 습관입니다.

핵심 원칙
민감정보는 최소 입력 · 불필요한 기록은 정리 · 외부 공유와 앱 권한은 정기 점검
01 · 개인 설정

8가지만 먼저 점검합니다.

기능 이름보다 중요한 것은 “어떤 정보가 남고, 어디로 이어지는가”입니다.

1

모델 개선 참여

설정 → 데이터 제어 → ‘모두를 위한 모델 개선’ 끄기

  • 대화가 모델 개선에 사용되는 것을 원치 않을 때 확인합니다.
  • 이 설정을 꺼도 일반 대화가 자동 삭제되는 것은 아닙니다.
교육 포인트 · 학습 거부와 저장·기록 삭제는 같은 기능이 아닙니다.
2

임시 채팅

비개인정보·비민감 업무에 제한적으로 사용

  • 일반 기록에 남지 않고 메모리를 만들지 않습니다.
  • 민감정보를 입력해도 된다는 의미는 아닙니다.
교육 포인트 · 임시 채팅을 ‘보안 모드’로 오해하지 않게 안내합니다.
3

메모리

설정 → 개인 맞춤 설정 → 메모리 관련 항목 확인

  • 저장된 메모리와 채팅 기록 참조 여부를 점검합니다.
  • 과거 정보가 다른 업무에 재사용되는 위험을 줄일 수 있습니다.
교육 포인트 · 공용 계정과 민감 프로젝트는 보수적으로 설정합니다.
4

저장된 메모리

설정 → 개인 맞춤 설정 → 메모리 관리

  • 기존 저장 내용을 확인하고 불필요 항목을 삭제합니다.
  • 채팅 삭제와 저장 메모리 삭제는 별도로 확인합니다.
교육 포인트 · 완전히 제거하려면 관련 채팅과 메모리를 각각 점검합니다.
5

대화 기록

업무 종료 후 불필요한 대화와 첨부 파일 정리

  • 계약·인사·상담 등은 조직의 보존 정책을 우선합니다.
  • 삭제가 필요한 대화는 정기적으로 점검합니다.
실무 원칙 · ‘언젠가 쓸지도 모른다’는 이유로 모든 기록을 남기지 않습니다.
6

공유 링크

필요할 때만 생성하고, 사용이 끝나면 회수

  • 민감한 대화는 공유 링크로 전달하지 않습니다.
  • 기존 공유 링크 목록을 주기적으로 검토합니다.
실무 원칙 · 링크는 복사된 뒤 통제하기 어렵다는 점을 기억합니다.
7

외부 앱 연결

사용하지 않는 앱·플러그인 연결 해제 + 권한 재검토

  • 연결 앱마다 별도의 접근 권한과 보존 정책이 적용될 수 있습니다.
  • 필요한 범위만 허용하고 사용이 끝나면 정리합니다.
실무 원칙 · 편리함보다 접근 범위를 먼저 확인합니다.
8

계정 보안

설정 → 보안 → 다중 인증 활성화

  • 로그인 시 두 번째 인증 단계를 추가합니다.
  • 필요하면 모든 기기 로그아웃도 함께 점검합니다.
실무 원칙 · 비밀번호 유출을 가정하고 두 번째 방어선을 만듭니다.
02 · 입력 보안 원칙

설정보다 먼저,
입력 습관을 바꿉니다.

가장 강한 보안은 애초에 불필요한 개인정보를 입력하지 않는 것입니다.

그대로 입력하지 말 것

  • 주민등록번호·계좌번호·비밀번호·인증번호
  • 실명과 결합된 상담·의료·인사·징계 정보
  • 고객 명단·계약서 원문·미공개 사업 정보
  • 조직에서 외부 반출이 금지된 파일과 데이터

이렇게 처리할 것

  • 이름·연락처·식별번호를 가명 또는 범주로 치환
  • 전체 문서 대신 필요한 문단과 데이터만 최소 입력
  • 민감 수치·고유명사·사건명을 일반화
  • 업무 종료 후 대화·메모리·공유·앱 권한 재점검
03 · 직원 개인 체크리스트
