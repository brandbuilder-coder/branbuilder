# 브랜드빌더 디자인 레퍼런스

## 목표

레퍼런스를 **목적 → 관찰 → 원리 추출 → 전환 → 검증** 순서로 실제 작업에 연결한다. 작품 이름이나 유행보다 브랜드가 전달할 강점과 정보의 우선순위를 먼저 정한다. 문헌과 실무를 결합한 작업 체계이며 과학적으로 검증된 단일 미학 이론이라고 주장하지 않는다.

## 1. 작업 조건을 확정한다

- 목적, 대상, 핵심 메시지, 매체·판형, 결과물 형식, 기존 브랜드 규칙을 확인한다. 제공된 조건을 다시 묻지 않는다.
- 빠진 값은 작업 가능한 범위에서 가정하고 밝힌다. 원본 수정 파일이나 명시된 첨부 팔레트처럼 대체할 수 없는 자료가 없을 때만 요청하고 독립적으로 가능한 작업은 진행한다.
- 지정한 팔레트·서체·로고를 우선한다. 팔레트가 보이지 않으면 임의로 추정하지 않는다.
- 브랜드빌더 자신의 콘텐츠에서 별도 지정이 없으면 Pretendard와 블랙·화이트·옐로우 방향을 기본 제안으로 사용한다. 정확한 색상값은 제공값 또는 제안값으로 구분한다. 고객 브랜드에는 자동 적용하지 않는다.
- 카드뉴스는 별도 지정이 없으면 4:5, 발표 자료는 16:9를 시작 조건으로 제안한다. 고정 템플릿에 내용을 끼워 맞추지 않는다.

## 2. 자료를 선택하고 실제로 확인한다

- [source-catalog.md](references/source-catalog.md)를 읽고 필요한 역할의 사이트와 후보를 고른다. 매번 13곳을 모두 검색하지 않는다.
- 제공 이미지와 프로젝트를 먼저 확인한다. 시각 분석은 실제 이미지·스크린샷을 본 범위에서만 한다. 검색 요약·텍스트만으로 배치·색·조명을 관찰했다고 말하지 않는다.
- 현재 기능·링크·권리 조건은 공식 자료를 확인한다. 정보 조회에는 검색과 읽기 도구를, 직접 상호작용에는 적절한 연결 도구를 사용한다.
- 작가·작품명·개별 URL·확인 날짜·관찰 범위를 기록한다. 사이트 전체를 단일 미학이나 품질의 보증으로 취급하지 않는다.
- 자료가 없거나 접근이 막히면 그 범위를 밝히고 사용 가능한 자료로 진행한다. 일반 원리 제안을 특정 작품 분석인 것처럼 포장하지 않는다.

## 3. 관찰을 설계 변수로 바꾼다

- [visual-principles.md](references/visual-principles.md)에서 관련 원리를 읽는다. 이론·사실 근거가 필요하면 [sources.md](references/sources.md)의 원자료를 확인한다.
- 위계, 정렬선, 큰·작은 여백, 상대 크기, 색 역할, 활자 밀도, 사진 구도·빛을 필요한 범위에서 기록한다.
- [transfer-and-qa.md](references/transfer-and-qa.md)의 관찰 카드로 **관찰 사실 / 해석 / 제안값 / 미확인 사항**을 구분한다.
- “세련됨·고급스러움·감성적”이라는 인상을 관찰 가능한 관계로 풀어 쓴다. 예: 제목과 본문의 크기 차이, 배경 단순함, 채도 대비, 그림자 경계.
- 근거 없는 최적 비율·고정 색채심리·조회 수에 따른 우수성·미감 점수를 만들지 않는다.

## 4. 브랜드 내용과 자산으로 구현한다

- 가져올 원리와 바꿀 요소를 연결한다. 예: 공통 정렬선 → 우리 한글 문장에 맞춘 열과 행갈이; 사진의 문구 여백 → 우리 음식 촬영의 프레이밍.
- 승인 팔레트가 있으면 배색 역할·대비 구조를 그 팔레트로 전환한다. 원본 색을 임의로 추가하지 않는다.
- 제작 요청에는 실제 산출물을 만든다. 프롬프트·설명만 전달하고 완료했다고 말하지 않는다. PPTX·문서·이미지·벡터 등 출력에 맞는 도구와 관련 지침을 따른다.
- 로고 설계·진단에는 설치된 `design-brand-logos`가 있으면 함께 사용해 문자·심벌 조형과 축소 검증을 수행한다. 사진 편집·생성은 제공 이미지 도구 지침을 따르고 정확한 도해는 벡터·도형으로 만든다.
- 촬영·카메라 오버레이는 [transfer-and-qa.md](references/transfer-and-qa.md)의 절차를 사용한다. 지원하지 않는 기능이나 실시간 제어를 완료했다고 주장하지 않는다.
- 삽입할 외부 자산은 해당 사용 조건을 확인한다. 독특한 로고·레터링·캐릭터·작품 전체를 그대로 재현해 독자적 결과물로 설명하지 않는다.

## 5. 실제 크기에서 검수하고 전달한다

- 판형, 정렬, 위계, 여백, 색 대비, 한글 행갈이, 크롭, 브랜드 적합성을 확인한다. 다중 페이지는 전체 일관성과 개별 페이지를 모두 본다.
- 대비·수치·파일 검사 등은 실제 수행한 범위만 완료로 표시한다. 남은 제약과 수정 사항은 구체적으로 밝힌다.
- 결과물 또는 적용안을 먼저 제시하고 선택 이유 → 적용 규칙 → 검수 결과 순서로 설명한다. 분석 요청에는 출처와 관찰 범위를 포함한다.
- 파일 저장·링크는 현재 환경의 전달 지침을 따른다. 외부 게시·공유·공개 보드 생성은 요청이 있을 때 수행한다.
