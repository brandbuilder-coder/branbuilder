# 브랜드빌더 전자책 제작
-by Brandbuilder-

## 목적과 범위
독자가 자신의 강점을 발견하고, 고객에게 기억될 이유를 정의하고, 실행할 수 있는 책을 제작하라. 정보 나열보다 판단 기준·근거·현장 적용을 연결하라.

BookForge의 주제/원고 분기, 콘텐츠와 조판 분리, 책의 구성 요소, 검수 후 납품 원칙을 참고한 독립 워크플로우 스킬이다. BookForge 실행 엔진·폰트·템플릿을 이 폴더에 포함한 것으로 간주하지 마라. 원작과 관계는 [references/bookforge.md](references/bookforge.md)를 읽어 확인하라.

## 1. 제작 브리프
사용자 요청과 제공 자료에서 다음을 추출해 프로젝트의 brief.md에 기록하라.
- 핵심 독자와 현재 문제, 읽은 뒤 달라질 행동 한 가지.
- 브랜드의 실제 강점, 차별성의 근거, 약속과 실행할 수 있는 범위.
- 주제/원고 모드, 원고 보존 수준, 판형, 분량, 최종 형식.
- 출처, 자산 사용권, 로고 유무, 사례 공개 가능 범위.

기존 맥락으로 해결되는 사항은 다시 묻지 마라. 사실·권한·핵심 목적이 없어 결과가 달라지는 경우에만 질문하라. 기본값은 한국어, 존대말, PDF, 153×225mm, 6개 장, 40~60쪽 목표다. 60~100쪽 등 사용자가 지정한 분량을 우선하라. 쪽수는 내용으로 확보하고 여백·부록·반복으로 부풀리지 마라.

브랜드빌더용 기본 디자인은 [references/design.md](references/design.md)를 적용하라. 다른 브랜드의 공식 가이드가 있으면 해당 가이드를 우선하고 제작자 크레딧만 유지하라.

## 2. 입력 모드
- 주제 모드: 출처 조사 → 핵심 주장 → 목차 → 장별 원고로 진행하라.
- 원고 모드: 원본 보존 → 구조 진단 → 중복 정리 → 용어 통일 → 조판 순서로 진행하라. 맞춤법·편집 수정과 내용 변경을 구분해 기록하라. 저자의 결론이나 사례를 임의로 바꾸지 마라.
- 자료 혼합 모드: 자료별 출처와 버전을 기록하고 충돌하는 사실을 먼저 확인하라.
- 사용자가 목차만 원하면 그 범위에서 완료하라. 책 제작 요청이면 목차만 제시하고 끝내지 마라.

## 3. 브랜드 관점과 집필
[references/editorial.md](references/editorial.md)를 읽고 다음 구조를 적용하라.
1. 한 문장 브랜드 약속: 누구의 어떤 문제를 어떤 강점으로 해결하는가.
2. 강점의 증거: 관찰, 실제 사례, 데이터와 적용 한계.
3. 포지셔닝: 고객의 선택 기준에서 차이가 무엇인가.
4. 고객 경험: 메시지가 상품·공간·응대·운영에서 어떻게 드러나는가.
5. 지속가능성: 역할, 반복할 기준, 속도, 측정과 개선.

각 장은 핵심 질문 → 개념 정의 → 판단 기준 → 사례 → 적용 도구 → 실행 질문 순서로 구성하되 주제에 맞게 변주하라. 모든 장을 같은 박스 레이아웃으로 찍어내지 마라.

제목·표지 카피를 개발할 때는 서로 다른 전략의 훅 5개 이상을 제시하고 각각 작동 이유를 한 문장으로 설명하라. 추천 1개로 진행하되 확정되지 않은 권위·성과·수치로 관심을 유도하지 마라.

## 4. 원고와 책 구조
프로젝트는 스킬 폴더 밖에 만들고 아래 파일을 유지하라.
- brief.md: 독자, 목적, 형식, 결정사항.
- outline.json: 장 순서, 제목, 요약, 원고 파일, 목차용 문장.
- chapters/ch-01.md 등: 장별 수정 가능한 원고.
- sources.md: 주장, 출처 URL/문서, 날짜, 적용 한계.
- assets/: 사용권이 확인된 로고·도해·사진.
- draft/, qc/, final/: 초안, 검수, 확정 산출물.

표지 → 판권/사용 안내 → 독자에게 주는 약속 → 쪽번호 있는 목차 → 본문 → 실행 워크시트 → 필요한 참고문헌/용어집 → 마무리 순서로 설계하라. 용어집과 부록은 실제 이해에 필요할 때만 넣어라. 저자·제작자·원작 소프트웨어의 크레딧을 구분하라.

## 5. 제작 경로
실제 실행 환경과 요청 형식에 맞춰 경로를 선택하고 brief.md에 남겨라.
- BookForge가 설치되어 있고 기존 스타일이 적합하면 references/bookforge.md의 검증된 명령을 사용하라. 자체 폴더에 원작 scripts가 있다고 가정하지 마라.
- 브랜드빌더 조형과 판형을 정확하게 구현하려면 사용 가능한 PDF/문서 제작 도구로 직접 조판하라. 해당 도구의 제작·렌더 검수 절차를 적용하라. 이 경로의 결과를 BookForge QC 통과라고 표현하지 마라.
- BookForge 스타일을 직접 확장할 때만 원작 references/extending.md를 읽고 해당 계약과 테스트를 수행하라. 색상 한 줄만 바꿔 브랜드빌더 테마 완성이라고 보고하지 마라.
- PPTX를 요청받으면 편집 가능한 텍스트·도형으로 별도 제작하라. 책 PDF를 장당 이미지로 붙인 파일을 편집 가능한 PPTX라고 부르지 마라. PDF와 내용·수치·출처를 대조하라.
- EPUB 요청은 리플로우 구조와 별도 검증 도구가 있는 경우에 수행하고, PDF 이름만 바꿔 제공하지 마라.
의존성이 없으면 허용된 설치나 실행 가능한 대체 경로를 먼저 시도하라. 출력이 불가능하면 완료된 원고와 막힌 출력 단계를 명확히 구분하라.

## 6. 납품 전 검수
[references/quality.md](references/quality.md)의 체크리스트를 수행하라.
PDF 파일 존재만으로 완료하지 마라. 모든 페이지를 렌더해 전체 흐름을 보고 표지·목차·장 시작·밀도 높은 본문·표/도해·마지막 페이지는 확대 확인하라. 오류를 고친 후 다시 렌더하라.
최종 PDF, 수정 가능한 원고, 요청된 편집 파일을 제공하라. 실제 수행한 검증과 남은 제한을 짧게 설명하라. 사용자 지시 없이 공개 업로드·배포하지 마라.

## 사용 예시
- “소상공인이 매장 강점을 찾는 전자책을 60쪽 내외로 만들어줘. -by Brandbuilder-”
- “이 원고의 논지는 유지하고 로고·도해 중심의 흑백·옐로우 PDF로 편집해줘.”
- “퍼스널브랜딩 5단계를 교육용 전자책과 편집 가능한 PPTX로 만들어줘.”
